Интернет-магазин лимитированной коллекции бильярдного мела для домена **kamui-collection.ru**.

## 1. Запуск на своём компьютере

Нужен **Node.js 20.9 или новее** (скачайте LTS-версию с nodejs.org).

```bash
npm install                 # установить зависимости (один раз)
cp .env.example .env.local  # файл настроек; на Windows можно просто скопировать вручную
npm run dev                 # открыть http://localhost:3000
```

Без Google Таблицы заявки сохраняются в файл `data/orders.jsonl` — этого достаточно, чтобы проверить форму.

Проверка перед выкладкой:

```bash
npm run build   # производственная сборка
npm start       # запустить собранный сайт на http://localhost:3000
npm run typecheck
```

> Сборку в песочнице, где писался проект, запустить было нельзя: npm там закрыт. Код проверен компилятором TypeScript, а сайт — в браузере на телефонных и компьютерных размерах экрана. Отправка заявок, Google Таблица, ЮKassa и СДЭК проверены на тестовых заглушках. Поэтому первый `npm run build` у вас — тоже часть проверки. Если он выдаст ошибку, пришлите её текст.

## 3. Google Таблица заказов (Сайт → Google Sheets)

Займёт около 10 минут, программировать не нужно.

1. Создайте новую Google Таблицу (sheets.new).
2. Откройте **Расширения → Apps Script**. Удалите всё, что там есть, и вставьте код из файла `integrations/google-sheets/apps-script.gs`.
3. В строке `const SECRET = "..."` впишите свою длинную случайную строку (например, 40 букв и цифр). Её нельзя никому показывать.
4. Необязательно: в `NOTIFY_EMAIL` впишите почту — туда будет приходить письмо о каждой новой заявке.
5. Сохраните проект. В списке функций выберите **setup** → **Выполнить** → разрешите доступ к таблице.
   Таблица переименуется в «Kamui Collection — Заказы», появятся листы «Заказы», «Международные заказы» и «Настройки».
6. **Начать развёртывание → Новое развёртывание → тип «Веб-приложение»**:
   - Запуск от имени: **Я**
   - У кого есть доступ: **Все**
7. Скопируйте URL веб-приложения (заканчивается на `/exec`) и пропишите в настройках сайта:
   ```
   GOOGLE_SHEETS_WEBHOOK_URL=https://script.google.com/macros/s/…/exec
   GOOGLE_SHEETS_SECRET=та-же-строка-что-и-в-скрипте
   ```
8. Перезапустите сайт и отправьте тестовую заявку — она появится в таблице.

Колонки листа «Заказы»: **ID заказа · Дата · Статус · Имя · Телефон · Email · Количество · Сумма · Город · Доставка · Комментарий** и служебная «Платёж» (заполнится после подключения ЮKassa).
Статус меняется из выпадающего списка: Новая → Оплачена → Отправлена → Доставлена.

Если вы поменяете код скрипта, сделайте **Развёртывание → Управление развёртываниями → Изменить → Новая версия**. Иначе будет работать старый код.

## 4. Остаток товара

```
Осталось = TOTAL_STOCK − SOLD_COUNT      (2000 − 49 = 1951)
```

- **Удобнее всего** менять `SOLD_COUNT` на листе «Настройки» Google Таблицы: сайт обновит цифру в течение минуты, пересобирать ничего не надо.
- Без таблицы используются переменные `TOTAL_STOCK` / `SOLD_COUNT` или значения в `src/config/stock.ts`.
- Остаток показывается в шапке, на первом экране, в разделе «Коллекция» и в блоке покупки. Сервер не примет заявку на большее количество, чем осталось. Когда остаток дойдёт до 0, появится «Тираж распродан».

Если хотите, чтобы продажи считались сами, впишите в ячейку `B3` формулу, например:
`=49+SUMIF(Заказы!C:C;"Оплачена";Заказы!G:G)+SUMIF(Заказы!C:C;"Отправлена";Заказы!G:G)`

## 5. Выкладка на kamui-collection.ru

### Вариант А — свой сервер в России (рекомендуется)

Подходит любой VPS с Ubuntu (Timeweb Cloud, Selectel, REG.RU, Yandex Cloud и т.п.), 1 ГБ памяти достаточно.

```bash
# на сервере: установить Docker (https://docs.docker.com/engine/install/ubuntu/)
git clone <ваш-репозиторий> kamui && cd kamui
cp .env.example .env && nano .env      # вписать настройки
mkdir -p data && sudo chown -R 1000:1000 data   # папка для заявок (сайт в контейнере работает от пользователя 1000)
docker compose up -d --build           # сайт запустится на 127.0.0.1:3000
```

Заявки хранятся в папке `data/` на сервере и сохраняются при обновлениях. Обновить сайт после изменений: `git pull && docker compose up -d --build`.

**Домен и HTTPS.**

1. У регистратора домена создайте A-записи `@` и `www` на IP сервера.
2. Поставьте nginx и бесплатный сертификат:

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo tee /etc/nginx/sites-available/kamui >/dev/null <<'NGINX'
server {
  server_name kamui-collection.ru www.kamui-collection.ru;
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
NGINX
sudo ln -s /etc/nginx/sites-available/kamui /etc/nginx/sites-enabled/ && sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d kamui-collection.ru -d www.kamui-collection.ru
```

### Вариант Б — Vercel (самый быстрый старт)

1. Загрузите проект на GitHub → vercel.com → **Add New Project** → выберите репозиторий.
2. В **Environment Variables** добавьте переменные из `.env.example`. Обязательно `ORDERS_FILE_STORE=false`: на Vercel нельзя писать файлы, заявки пойдут только в Google Таблицу.
3. **Settings → Domains** → добавьте `kamui-collection.ru` и пропишите у регистратора записи, которые покажет Vercel.

Учтите: серверы Vercel находятся за границей, а бесплатный тариф не предназначен для коммерческих сайтов. Для постоянной работы магазина лучше вариант А.

## 6. Подключение ЮKassa (когда будете готовы)

1. Зарегистрируйте магазин на yookassa.ru. Для модерации на сайте понадобятся: цена, реквизиты (уже есть), контакты (заполните `SELLER.email/phone`), **публичная оферта**, условия доставки и возврата. Эти страницы можно добавить по образцу `src/app/privacy`.
2. В `.env` пропишите:
   ```
   PAYMENTS_ENABLED=true
   YOOKASSA_SHOP_ID=…
   YOOKASSA_SECRET_KEY=…
   YOOKASSA_SEND_RECEIPT=true   # если подключены «Чеки от ЮKassa» (54-ФЗ)
   ```
3. В личном кабинете ЮKassa → Интеграция → HTTP-уведомления укажите
   `https://kamui-collection.ru/api/payments/yookassa/webhook`, события `payment.succeeded` и `payment.canceled`.

Как это устроено: после заявки создаётся платёж и покупатель переходит на страницу оплаты. Затем ЮKassa присылает уведомление. Сайт перепроверяет платёж через API ЮKassa и ставит в таблице статус «Оплачена». Код: `src/lib/payments/yookassa.ts`.

## 7. Подключение СДЭК

1. Получите ключи API в личном кабинете СДЭК (Интеграция). Для проверки подойдёт учебная среда: `CDEK_TEST_MODE=true`.
2. Заполните `CDEK_*` в `.env` и поставьте `CDEK_ENABLED=true`.
3. Готовые маршруты:
   - `GET /api/delivery/cdek/cities?q=Краснодар` — поиск города (код города),
   - `GET /api/delivery/cdek/points?cityCode=…` — пункты выдачи,
   - `POST /api/delivery/cdek/calculate` `{ cityCode, quantity }` — стоимость и срок.
4. Создание отправления и номер для отслеживания: функции `createShipment()` и `getTrackingNumber()` в `src/lib/delivery/cdek.ts`.
   В заказе уже предусмотрены поля ПВЗ, стоимости доставки, UUID и трек-номера (`src/lib/orders/types.ts`).

Когда ключи будут, в форму добавляется выбор ПВЗ: список из `/points` или официальный виджет СДЭК.

## 8. Перед запуском: юридический чек-лист (152-ФЗ)

Это не юридическая консультация, а список того, что стоит проверить с юристом:

- [ ] Подать уведомление в Роскомнадзор об обработке персональных данных (pd.rkn.gov.ru).
- [ ] **Локализация.** Данные граждан РФ сначала записываются в базы на территории РФ. Поэтому сайт сохраняет каждую заявку в файл `data/orders.jsonl` на сервере: для этого сервер должен быть в России (вариант А). Google Таблица — вторая копия. Это трансграничная передача, о ней отдельно уведомляют Роскомнадзор. Можно и вовсе отказаться от таблицы.
- [ ] Проверить тексты «Политики конфиденциальности» и «Согласия на обработку ПДн». С 1 сентября 2025 года согласие оформляется отдельным документом, поэтому на сайте две отдельные страницы.
- [ ] Дописать в реквизиты город и индекс в адресах (`src/config/site.ts`), указать контактный email/телефон.
- [ ] Перед онлайн-оплатой: оферта, условия доставки и возврата, онлайн-касса (54-ФЗ).
