## 1. Запуск на своём компьютере

Нужен **Node.js 20.9 или новее** (скачайте LTS-версию с nodejs.org).

```bash
npm install                 # установить зависимости (один раз)
cp .env.example .env.local  # файл настроек; на Windows можно просто скопировать вручную
npm run dev                 # открыть http://localhost:3000
```

Без Google Таблицы заявки сохраняются в файл `data/orders.jsonl` — этого достаточно, чтобы проверить форму.

Проверка перед выкладкой:

```bash
npm run build   # производственная сборка
npm start       # запустить собранный сайт на http://localhost:3000
npm run typecheck
```

> Сборку в песочнице, где писался проект, запустить было нельзя: npm там закрыт. Код проверен компилятором TypeScript, а сайт — в браузере на телефонных и компьютерных размерах экрана. Отправка заявок, Google Таблица, ЮKassa и СДЭК проверены на тестовых заглушках. Поэтому первый `npm run build` у вас — тоже часть проверки. Если он выдаст ошибку, пришлите её текст.

## 2а. База данных заказов (PostgreSQL в Timeweb Cloud)

Основное хранилище заказов — база PostgreSQL; Google Таблица остаётся копией для просмотра
(сайт дописывает туда заказы, но работает и без неё). Подключение — одна переменная в панели хостинга:

```
DATABASE_URL=postgresql://gen_user:ПАРОЛЬ@АДРЕС:5432/default_db   # Timeweb → база → «Показать данные подключения»
# необязательно:
# DATABASE_CA=-----BEGIN CERTIFICATE-----…   # сертификат Timeweb — тогда сайт ещё и проверяет сертификат базы
# (без него соединение всё равно шифруется, даже если в адресе стоит sslmode=verify-full)
```

- Таблицы создаются сами при первом подключении; старые заказы (оплаты ЮKassa + Google Таблица: Robokassa,
  ждущие оплаты, международные, отметки о письмах) переносятся автоматически один раз. Повторить перенос —
  кнопка «Обновить перенесённые заказы из таблицы и ЮKassa» на `/cdek-orders` (заказы, оформленные уже с базой, не трогает).
- В базе хранится всё о заказе, поэтому накладную СДЭК можно создать заново по одной кнопке; у каждого заказа
  на `/cdek-orders` есть история (оплата, накладная, письма, ошибки).
- Персональные данные покупателей записываются в базу в России (152-ФЗ); журнал согласий — таблица `consents`.
- Если база временно недоступна, заказ всё равно принимается (в Google Таблицу), а страница `/cdek-orders` об этом пишет.
- Подключение к базе написано без сторонних библиотек (`src/lib/db/pg.ts`: SSL, SCRAM-SHA-256/MD5).

## 3. Google Таблица заказов (Сайт → Google Sheets)

Займёт около 10 минут, программировать не нужно.

1. Создайте новую Google Таблицу (sheets.new).
2. Откройте **Расширения → Apps Script**. Удалите всё, что там есть, и вставьте код из файла `integrations/google-sheets/apps-script.gs`.
3. В строке `const SECRET = "..."` впишите свою длинную случайную строку (например, 40 букв и цифр). Её нельзя никому показывать.
4. Необязательно: в `NOTIFY_EMAIL` впишите почту — туда будет приходить письмо о каждой новой заявке.
5. Сохраните проект. В списке функций выберите **setup** → **Выполнить** → разрешите доступ к таблице.
   Таблица переименуется в «Kamui Collection — Заказы», появятся листы «Заказы», «Международные заказы» и «Настройки».
6. **Начать развёртывание → Новое развёртывание → тип «Веб-приложение»**:
   - Запуск от имени: **Я**
   - У кого есть доступ: **Все**
7. Скопируйте URL веб-приложения (заканчивается на `/exec`) и пропишите в настройках сайта:
   ```
   GOOGLE_SHEETS_WEBHOOK_URL=https://script.google.com/macros/s/…/exec
   GOOGLE_SHEETS_SECRET=та-же-строка-что-и-в-скрипте
   ```
8. Перезапустите сайт и отправьте тестовую заявку — она появится в таблице.

Колонки листа «Заказы»: **ID заказа · Дата · Статус · Имя · Телефон · Email · Количество · Сумма · Город · Доставка · Комментарий** и служебная «Платёж» (заполнится после подключения ЮKassa).
Статус меняется из выпадающего списка: Новая → Оплачена → Отправлена → Доставлена.

Если вы поменяете код скрипта, сделайте **Развёртывание → Управление развёртываниями → Изменить → Новая версия**. Иначе будет работать старый код.

**Лист «Согласия»** — журнал согласий из формы заказа: дата и время, номер заказа, ФИО, почта, телефон, согласие на
обработку персональных данных (с редакцией текста согласия), согласие на письма о заказе, IP и браузер покупателя.
Строка добавляется вместе с заказом. Лист создаётся сам при первом заказе после обновления скрипта. Редакция текста
согласия — `SHOP.privacyEdition` в `src/config/site.ts`: при изменении политики или согласия обновите дату.


### Письма покупателям (отправляет сам сайт)

Сайт сам пишет покупателю с ящика магазина (SMTP Timeweb):

- **«Спасибо за заказ»** — сразу после оплаты (ЮKassa и Robokassa);
- **трек-номер СДЭК** с кнопкой «Отследить посылку» — как только СДЭК присвоил номер накладной;
- **напоминание о сроке хранения** — за 2 дня до конца бесплатного хранения в пункте выдачи.

Проверка трек-номеров и сроков хранения идёт раз в 30 минут; на странице `/cdek-orders?token=…` видно, какие письма
ушли по каждому заказу, сколько дней осталось хранения, и есть кнопка «Проверить и отправить письма покупателям».
Отметки об отправленных письмах сайт пишет в колонку «Письма покупателю» листа «Заказы» — повторно то же письмо не уйдёт.

Настройки (панель Timeweb → переменные окружения):

```
SMTP_USER=shop@abramov.shop
SMTP_PASSWORD=пароль-от-ящика
# необязательно:
SMTP_HOST=smtp.timeweb.ru        # по умолчанию
SMTP_PORT=465                    # по умолчанию (SSL); если не задан и 465 закрыт — сайт пробует 587
MAIL_TRANSPORT=auto              # auto — сервер Timeweb, при недоступности Gmail; sheets — только Gmail; smtp — только Timeweb
MAIL_FROM_NAME=Abramov Shop      # имя отправителя
CDEK_STORAGE_DAYS=7              # сколько дней посылка бесплатно лежит в ПВЗ (если СДЭК не сообщает дату сам)
STORAGE_REMIND_DAYS=2            # за сколько дней до конца хранения напомнить
MAIL_ENABLED=false               # выключить письма, не удаляя пароль
```

**Если хостинг закрыл почтовые порты** (на странице накладных ошибка «SMTP: нет соединения с smtp.timeweb.ru…»),
письма уходят через скрипт таблицы: он отправляет их из Gmail владельца таблицы от имени shop@abramov.shop.
Для этого адрес shop@abramov.shop должен быть в Gmail → Настройки → Аккаунты и импорт → «Отправлять письма как»,
а в Apps Script один раз выполнена функция `checkMail` (Google спросит разрешение на отправку писем).
Покупатель видит то же: отправитель и адрес для ответа — shop@abramov.shop. Лимит Gmail — около 100 писем в сутки.

Нужен основной скрипт таблицы новой версии (`apps-script.gs`: отметки о письмах, список оплаченных заказов, отправка через Gmail) —
без него проверка по расписанию ничего не отправляет, чтобы письма не ушли дважды.
Отдельный скрипт «Письма покупателям» в таблице больше не нужен — удалите его и выключите в нём автоотправку,
иначе покупатель получит письма дважды.

## 4. Остаток товара

```
Осталось = TOTAL_STOCK − (SOLD_COUNT + оплачено на сайте)
```

- **Оплаченные на сайте заказы вычитаются сами**: сайт суммирует количество по успешным платежам ЮKassa
  (тестовые и полностью возвращённые платежи не считаются). Цифра на сайте обновляется в течение минуты,
  а при подключённых уведомлениях ЮKassa — сразу после оплаты.
- `SOLD_COUNT` на листе «Настройки» Google Таблицы — **продажи вне сайта** (до запуска, из рук в руки, по заявкам без онлайн-оплаты).
  Меняйте его вручную только для таких продаж: сайт обновит цифру в течение минуты, пересобирать ничего не надо.
- Не вписывайте в `B3` формулу, которая сама считает оплаченные заказы из листа «Заказы», — иначе они посчитаются дважды.
- Без таблицы используются переменные `TOTAL_STOCK` / `SOLD_COUNT` или значения в `src/config/stock.ts`.
- `STOCK_COUNT_PAID=false` — отключить автоматический учёт оплат; `STOCK_COUNT_SINCE` — с какой даты считать платежи (по умолчанию 01.09.2026).
- Проверить, из чего складывается остаток: `/pay-check?token=<PAYMENTS_TEST_TOKEN>` → блок `stock`.
- Остаток показывается в шапке, на первом экране, в разделе «Коллекция» и в блоке покупки. Сервер не примет заявку на большее количество, чем осталось. Когда остаток дойдёт до 0, появится «Тираж распродан».

## 5. Выкладка на kamui-collection.ru

### Вариант А0 — Timeweb Cloud App Platform (Москва, без администрирования)

1. В панели Timeweb Cloud: **App Platform → Создать → Dockerfile**, подключить GitHub, репозиторий `Kamui`, ветка `site`.
2. Регион — **Москва**, конфигурация — минимальная. Автодеплой — включить (каждый push в ветку обновляет сайт).
3. Переменные окружения — только секреты (остальные настройки магазина уже заданы в `Dockerfile`):
   `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET`, `YOOKASSA_SECRET_KEY`, `GOOGLE_SHEETS_WEBHOOK_URL`, `GOOGLE_SHEETS_SECRET`,
   `PAYMENTS_TEST_TOKEN` (для служебной проверки `/pay-check`).
4. Проверить на техническом домене `*.twc1.net`, затем привязать `kamui-collection.ru` и направить на него DNS в REG.RU.
5. В ЮKassa указать адрес уведомлений `https://kamui-collection.ru/api/payments/yookassa/webhook`.

Диск контейнера не сохраняется между обновлениями, поэтому заявки хранятся в Google Таблице (`ORDERS_FILE_STORE=false`).

### Вариант А — свой сервер в России (рекомендуется)

Подходит любой VPS с Ubuntu (Timeweb Cloud, Selectel, REG.RU, Yandex Cloud и т.п.), 1 ГБ памяти достаточно.

```bash
# на сервере: установить Docker (https://docs.docker.com/engine/install/ubuntu/)
git clone <ваш-репозиторий> kamui && cd kamui
cp .env.example .env && nano .env      # вписать настройки
mkdir -p data && sudo chown -R 1000:1000 data   # папка для заявок (сайт в контейнере работает от пользователя 1000)
docker compose up -d --build           # сайт запустится на 127.0.0.1:3000
```

Заявки хранятся в папке `data/` на сервере и сохраняются при обновлениях. Обновить сайт после изменений: `git pull && docker compose up -d --build`.

**Домен и HTTPS.**

1. У регистратора домена создайте A-записи `@` и `www` на IP сервера.
2. Поставьте nginx и бесплатный сертификат:

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo tee /etc/nginx/sites-available/kamui >/dev/null <<'NGINX'
server {
  server_name kamui-collection.ru www.kamui-collection.ru;
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
NGINX
sudo ln -s /etc/nginx/sites-available/kamui /etc/nginx/sites-enabled/ && sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d kamui-collection.ru -d www.kamui-collection.ru
```

### Вариант Б — Vercel (самый быстрый старт)

1. Загрузите проект на GitHub → vercel.com → **Add New Project** → выберите репозиторий.
2. В **Environment Variables** добавьте переменные из `.env.example`. Обязательно `ORDERS_FILE_STORE=false`: на Vercel нельзя писать файлы, заявки пойдут только в Google Таблицу.
3. **Settings → Domains** → добавьте `kamui-collection.ru` и пропишите у регистратора записи, которые покажет Vercel.

Учтите: серверы Vercel находятся за границей, а бесплатный тариф не предназначен для коммерческих сайтов. Для постоянной работы магазина лучше вариант А.

## 6. Подключение ЮKassa

1. Зарегистрируйте магазин на yookassa.ru. Для модерации на сайте уже есть всё нужное: цена, реквизиты, **публичная оферта** (`/oferta`), **доставка и оплата** (`/delivery`), **обмен и возврат** (`/returns`). Останется вписать контакты: `SELLER.email` и `SELLER.phone` в `src/config/site.ts`.
2. Подключите онлайн-кассу (54-ФЗ): проще всего «Чеки от ЮKassa» в личном кабинете.
3. Задайте переменные окружения (на Vercel: Settings → Environment Variables) и пересоберите сайт:
   ```
   PAYMENTS_ENABLED=true
   YOOKASSA_SHOP_ID=…
   YOOKASSA_SECRET_KEY=…
   YOOKASSA_SEND_RECEIPT=true
   ```
4. В личном кабинете ЮKassa → Интеграция → HTTP-уведомления укажите
   `https://kamui-collection.ru/api/payments/yookassa/webhook`, события `payment.succeeded` и `payment.canceled`.

Как это устроено:
- Покупатель оформляет заказ, сайт создаёт платёж и отправляет покупателя на страницу ЮKassa. В таблице появляется строка со статусом «Ожидает оплаты».
- После оплаты покупатель возвращается на сайт (`/?order=<номер>`) и видит статус: сайт спрашивает его у ЮKassa (`/api/payments/status`).
- ЮKassa присылает уведомление. Сайт перепроверяет платёж через API и ставит статус «Оплачена» или «Оплата отменена».
- Международные заказы онлайн не оплачиваются: менеджер связывается вручную.

Если ЮKassa или СДЭК временно недоступны, заявка всё равно сохраняется: без оплаты, со статусом «Новая».

Код: `src/lib/payments/yookassa.ts`, `src/app/api/orders/route.ts`, `src/app/api/payments/*`.

## 7. Подключение СДЭК

1. Заключите договор со СДЭК как интернет-магазин и получите ключи API: lk.cdek.ru → Интеграция.
2. Задайте переменные окружения:
   ```
   CDEK_ENABLED=true
   CDEK_TEST_MODE=false
   CDEK_CLIENT_ID=…
   CDEK_CLIENT_SECRET=…
   CDEK_FROM_CITY_CODE=…    # код вашего города в справочнике СДЭК
   CDEK_SHIPMENT_POINT=…    # код ПВЗ, куда вы сдаёте посылки
   ```
   Упаковка одной штуки — `CDEK_ITEM_*` (сейчас 26 × 18 × 1 см, 23 г). Подарочный набор — `CDEK_KIT_*` (по умолчанию 30 × 22 × 8 см, 400 г; каждый набор — отдельное место в посылке). В набор кладётся один мел из тиража, поэтому набор уменьшает остаток так же, как мел; в таблице заказ набора виден по первой строке комментария: «Подарочный набор × N · наклейка JOS H+». Страховка объявленной стоимости (стоимость мела в заказе) входит в стоимость доставки: сайт просит СДЭК посчитать тариф вместе с услугой «Страхование», а в таблице видно «тариф СДЭК N ₽, в т. ч. страховка M ₽». Отключить — `CDEK_INSURANCE=false`; `CDEK_INSURANCE_PERCENT` (0,75 %) используется, только если СДЭК не вернул сумму страховки. Кто платит за доставку — `DELIVERY_PRICE_MODE` (`customer` или `free`). Наценка к тарифу СДЭК — `DELIVERY_MARKUP_PERCENT` (сейчас 30 %) плюс 5 п. п. сверху (`DELIVERY_MARKUP_EXTRA` в `src/config/features.ts`), итого 35 %: покупатель видит цену с наценкой, в таблице видны обе суммы.
3. Что появляется на сайте:
   - в форме заказа — поиск города, список пунктов выдачи с поиском по улице, стоимость и срок доставки;
   - сумма к оплате = товар + доставка, в чеке это две позиции;
   - после оплаты отправление в СДЭК создаётся автоматически, а трек-номер дописывается в колонку «Доставка» таблицы. Выключить: `CDEK_AUTO_SHIPMENT=false`.
   - страна доставки: Россия или «Другая страна» — заявка менеджеру. Можно включить СДЭК с оплатой на сайте и для стран ЕАЭС — Беларусь, Казахстан, Армения, Кыргызстан (без таможни, тот же тариф 136): переменная `CDEK_COUNTRIES=RU,BY,KZ,AM,KG` в панели хостинга, код менять не нужно. Для заказов за пределы России в накладную добавляются поля международного заказа (продавец, грузоотправитель, дата инвойса). Если СДЭК отклонит накладную, в колонке «Доставка» появится пометка с причиной — оформите отправление вручную в lk.cdek.ru. По умолчанию (переменная не задана) — только Россия.
4. Маршруты: `GET /api/delivery/cdek/cities?q=&country=BY`, `GET /api/delivery/cdek/points?cityCode=`, `POST /api/delivery/cdek/calculate`.

### Robokassa — оплата заказов за пределы России

Заказы с доставкой СДЭК в Беларусь, Казахстан, Армению и Кыргызстан оплачиваются через Robokassa — она принимает карты Visa, Mastercard и UnionPay зарубежных банков. По России оплата по-прежнему через ЮKassa, заявки в другие страны — менеджеру.

1. Личный кабинет Robokassa → Мои магазины → Технические настройки: скопируйте идентификатор магазина, пароли №1 и №2 и посмотрите алгоритм хеша. Там же укажите
   Result URL `https://kamui-collection.ru/api/payments/robokassa/result` (POST), Success URL `…/api/payments/robokassa/success` (GET), Fail URL `…/api/payments/robokassa/fail` (GET).
2. В панели хостинга: `ROBOKASSA_LOGIN`, `ROBOKASSA_PASSWORD1`, `ROBOKASSA_PASSWORD2`, при необходимости `ROBOKASSA_HASH` (по умолчанию md5). Для пробных платежей — `ROBOKASSA_TEST=true` и тестовые пароли.
3. Проверка: `/pay-check?token=<PAYMENTS_TEST_TOKEN>` → блок `robokassa`, поле `keys` должно быть `ok`.
4. После оплаты Robokassa вызывает Result URL: заказ в таблице становится «Оплачена», в колонке «Платёж» — «Robokassa · оплачено …», создаётся накладная СДЭК.
   Если уведомление до сайта не дошло (Result URL не указан или указан неверно, сбой сети), сайт сам сверяет
   заказы «Ожидает оплаты» со счётом Robokassa за последние 14 дней — раз в 30 минут и при открытии `/cdek-orders` —
   и, если счёт оплачен, делает то же самое: «Оплачена», письмо покупателю, накладная СДЭК.
   Свежие оплаты (до 6 часов, `AUTO_SHIP_RETRY_HOURS`) без накладной — и ЮKassa, и Robokassa — проверка раз в 30 минут
   тоже доводит до накладной сама; заказы постарше — кнопкой «Создать накладную» на `/cdek-orders`.
5. Цены для заказов из-за рубежа — в долларах: мел `PRICE_USD` (по умолчанию $48; от 10 шт. — `WHOLESALE_PRICE_USD`, по умолчанию $41), доставка — цена СДЭК для покупателя + `ABROAD_MARKUP_PERCENT` (по умолчанию 11%), округление вверх до доллара. К оплате — рубли по курсу ЦБ на день заказа. Для Казахстана и Кыргызстана в форме обязателен ИИН / ПИН получателя: он пишется первой строкой в «Комментарий» и уходит в накладную СДЭК (recipient.tin).
6. Остаток: сайт сам вычитает только оплаты ЮKassa. Чтобы учитывались и оплаты Robokassa, в листе «Настройки» в ячейке B3 вместо числа N впишите
   `=N+SUMIF(Заказы!L:L;"Robokassa*";Заказы!G:G)` (L — колонка «Платёж», G — «Количество»).

СДЭК работает и без ЮKassa: тогда в заявке сохраняются выбранный ПВЗ и стоимость, а оплату менеджер выставляет вручную.

## 8. Перед запуском: юридический чек-лист (152-ФЗ)

Это не юридическая консультация, а список того, что стоит проверить с юристом:

- [ ] Подать уведомление в Роскомнадзор об обработке персональных данных (pd.rkn.gov.ru).
- [ ] **Локализация.** Данные граждан РФ сначала записываются в базы на территории РФ. Поэтому сайт сохраняет каждую заявку в файл `data/orders.jsonl` на сервере: для этого сервер должен быть в России (вариант А). Google Таблица — вторая копия. Это трансграничная передача, о ней отдельно уведомляют Роскомнадзор. Можно и вовсе отказаться от таблицы.
- [ ] Проверить тексты «Политики конфиденциальности» и «Согласия на обработку ПДн». С 1 сентября 2025 года согласие оформляется отдельным документом, поэтому на сайте две отдельные страницы.
- [ ] Дописать в реквизиты город и индекс в адресах (`src/config/site.ts`), указать контактный email/телефон.
- [ ] Перед онлайн-оплатой: проверить тексты оферты, условий доставки и возврата (`/oferta`, `/delivery`, `/returns`), подключить онлайн-кассу (54-ФЗ).
